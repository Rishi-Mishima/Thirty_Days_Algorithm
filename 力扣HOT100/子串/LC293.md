## 核心解法一：单调双端队列 (Monotonic Deque)

解决此题的最优数据结构是**单调双端队列（Monotonic Queue）**，能够将复杂度降低至 O(n)。

**队列维护逻辑：**

1. 队列中存储元素的**下标**（方便判断元素是否离开窗口）。
2. 保持队列中下标对应的元素值**严格单调递减**。
3. **入队操作**：当新元素入队时，将队列末尾所有**小于当前元素**的下标全部弹出（因为这些较小的元素永远不可能再成为后续窗口的最大值了）。
4. **出队操作**：检查队头元素对应的下标，如果已经超出了当前窗口左边界，将其从队头弹出。
5. **记录结果**：每一轮的**队头元素**即为当前窗口的最大值。



```python 
from collections import deque


class Solution:

  def maxSlidingWindow(self, nums: list[int], k: int) -> list[int]:
    q = deque()  # 存储下标，保持 nums[q[i]] 单调递减
    res = []

    for i, num in enumerate(nums):
      # 1. 维持单调性：移除队列中所有比当前元素小的尾部下标
      while q and nums[q[-1]] < num:
        q.pop()

      # 2. 将当前下标入队
      q.append(i)

      # 3. 移除过期元素：如果队头下标超出了窗口范围 [i - k + 1, i]
      if q[0] <= i - k:
        q.popleft()

      # 4. 窗口形成后（i >= k - 1），队头即为当前窗口最大值
      if i >= k - 1:
        res.append(nums[q[0]])

    return res
```



### 二、 为什么不能（不适合）用堆（Priority Queue / Heap）？

在面对“动态求最大值”的场景时，大顶堆（Priority Queue）通常是第一直觉，但这道题**标准的大顶堆在时间复杂度上不满足要求**。

#### 1. 堆的痛点：无法高效删除“过期的非堆顶元素”

随着滑动窗口的右移，位于窗口最左侧的元素会**离开窗口**。如果使用大顶堆：

- 堆可以在 O(1) 时间获得最大值，并用 O(log k) 弹出**堆顶**元素。
- 但离开窗口的元素**不一定正好是堆顶**。要在标准堆中找到并删除一个**处于堆内部的指定元素**，需要遍历堆，时间复杂度是 O(k)，导致总时间复杂度退化为 **O(n * k)**（在 n, k <= 10^5 时会直接超时）。

问题出在：**大顶堆（Max-Heap）无法以 O(1) 或 O(log k) 的效率把“离开窗口的那个数”从堆里删掉**。

如果窗口大小固定为 3，窗口向右滑动 1 格时，发生了两件事：

1. **进来一个新数**（入堆）：简单，堆的 `push` 操作只要 O(log k)。
2. **离开一个旧数**（出堆）：**这里是最大的障碍！**



##### 为什么堆不能直接把“旧数”扔掉？

大顶堆的结构只保证**顶端（根节点）是最大的数**。对于堆内部的其他节点，堆**并没有记录位置**。

假设窗口里的 3 个数是 `[9, 2, 5]`，大顶堆在内存里的结构是：

- 堆顶是 `9`
- 堆内部是 `2` 和 `5`



下一步，窗口右移，最左边的 `2` 要离开窗口。

请问：**你怎么在堆里把 `2` 删掉？**

1. `2` 不是堆顶（堆顶是 9），所以你**不能直接用 `pop()`**。
2. 堆没有像数组下标或哈希表那样的快速定位能力。要找到 `2` 在堆里的位置，必须**把堆里的元素挨个遍历一遍**（耗费 O(k) 时间），找到 `2` 后把它删掉，再重新调整堆。

> **核心矛盾：**
>
> 每次窗口滑动，删掉过期元素需要 O(k) 时间。
>
> 整个数组遍历下来，总时间就是 O(n * k)。如果 k = 50,000，这就和暴力法一样慢了，直接超时！

####  如果用大顶堆（直接删除法）

```
窗口移动：[9, 2, 5] -> 移除 2 -> 加入 7
堆的操作：
1. 遍历堆找到 '2' 所在位置    -> 慢！耗时 O(k)
2. 删掉 '2' 并重新调整堆结构 -> 耗时 O(log k)
3. 插入 '7' 并调整           -> 耗时 O(log k)
```

#### 如果用单调队列（Deque）

单调队列是一个双端队列，**两头都能出入**：

```
窗口移动：[9, 2, 5] -> 移除 2 -> 加入 7
单调队列的操作：
1. 看最左边（队头）：是不是刚过期的 '2'？（如果是就弹出，不是不管） -> O(1)
2. 从右边（队尾）进 '7'：把比 '7' 小的废料（5）直接踢掉            -> O(1)
```





#### 2. 延迟删除法（Lazy Deletion）的缺陷

有人可能会想用懒惰删除（延迟删除）来避开内部删除问题：

- 将元素与下标打成元组 `(num, index)` 压入大顶堆。
- 只有当**堆顶**的下标落到窗口之外时，才把堆顶弹出。

**这种“大顶堆+延迟删除”法虽然能通过本题，但性能不是最优：**

- **时间复杂度**：在极端递增序列下（如 `[1, 2, 3, 4, 5...]`），堆的大小会一直膨胀，最大可以达到 O(n)。每次插入和弹出堆顶需要 O(log n) 时间，总时间复杂度为 **O(n log n)**。
- **空间复杂度**：最坏情况下堆的大小会达到 O(n)，而非滑动窗口要求的 O(k)。

### 三、 两种数据结构对比

| **机制 / 维度**      | **传统堆（大顶堆 + 延迟删除）**            | **单调双端队列（Monotonic Deque）**    |
| -------------------- | ------------------------------------------ | -------------------------------------- |
| **如何处理窗口过期** | 懒惰删除（只在过期元素刚好到堆顶时才弹出） | 主动弹出（队头过期立刻弹出，O(1)）     |
| **如何维护最大值**   | 维护全部窗口元素，依靠树状堆调整           | 入队时丢弃所有不可能成为最大值的旧元素 |
| **时间复杂度**       | O(n \log n)                                | **O(n)**（最优）                       |
| **空间复杂度**       | O(n)                                       | **O(k)**（最优）                       |

### 滑动窗口的代码框架

```python 
from collections import deque
from typing import List


class Solution:

  def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
    ans = []
    q = deque()  # deque 保存的是数组下标

    for i, x in enumerate(nums):  # x 即 nums[i]

      # 1. 入：维护队列单调性
      # 只要队尾元素 <= 当前新元素 x，就不断弹出队尾（把废料踢掉）
      while q and nums[q[-1]] <= x:
        q.pop()
      q.append(i)  # 当前下标 i 插入队尾

      # 2. 出：判断队首元素是否已经离开窗口
      # 当队首下标 q[0] 到当前下标 i 的距离 >= k 时，说明队首已经超期了
      if i - q[0] >= k:
        q.popleft()

      # 3. 记：从第 k - 1 个元素开始，每一步都要记录当前窗口的最大值
      if i >= k - 1:
        ans.append(nums[q[0]])  # 队首就是当前窗口内的最大值

    return ans
```

理解这段代码的核心关键在于：**队列里存的不是数字本身，而是数字的下标（`i`），并且队列中的下标所对应的数字，必须严格保持“从大到小”排列。**



### 步骤解析

#### 步骤 1：维持单调递减（`while q and nums[q[-1]] < num:`）

```python
while q and nums[q[-1]] < num:
  q.pop()
```

- **作用**：检查队尾（`q[-1]`）对应的数字是否小于当前新进来的数字 `num`。如果是，从队尾弹出。
- **直观理解**：就像新人入职，如果新人能力比老员工强，老员工又比新人先退休，那老员工就完全没有留下的价值了，直接解雇（弹出）。

#### 步骤 2：当前下标入队（`q.append(i)`）

```python
q.append(i)
```

- **作用**：把当前数字的**下标 `i`** 追加到队尾。经过步骤 1 的清理后，此时插入下标能保证队列对应的值依然是**单调递减**的。

#### 步骤 3：剔除过期元素（`if q[0] <= i - k:`）

```python
if q[0] <= i - k:
  q.popleft()
```

- **作用**：对于长度为 k 的窗口，当遍历到下标 `i` 时，合法的窗口下标范围是 `[i - k + 1, i]`。如果队头 `q[0]` 的下标小于等于 `i - k`，说明它已经划出窗口了，直接从左侧弹出（`popleft()`）。

#### 步骤 4：记录窗口最大值（`if i >= k - 1:`）

```python
if i >= k - 1:
  res.append(nums[q[0]])
```

- **作用**：当遍历的下标 `i` 达到了 `k - 1`，说明**第一个窗口已经正式形成**。此后每走一步都有一个完整窗口。因为队列是单调递减的，**队头 `q[0]` 对应的数字必然是当前窗口内的最大值**，直接加入结果列表。





## 核心解法2: 懒删除

对于「最大值」，我们可以用优先队列（堆），其中的**大根堆**可以帮助我们实时维护一系列元素中的最大值。

对于本题而言，初始时，我们将数组 nums 的前 k 个元素放入优先队列中。每当我们向右移动窗口时，我们就可以把一个新的元素放入优先队列中，此时堆顶的元素就是堆中所有元素的最大值。然而这个最大值可能并不在滑动窗口中，在这种情况下，这个值在数组 nums 中的位置出现在滑动窗口左边界的左侧。因此，当我们后续继续向右移动窗口时，这个值就永远不可能出现在滑动窗口中了，我们可以将其永久地从优先队列中移除。

我们不断地移除堆顶的元素，直到其确实出现在滑动窗口中。此时，堆顶元素就是滑动窗口中的最大值。为了方便判断堆顶元素与滑动窗口的位置关系，我们可以在优先队列中存储二元组 (num,index)，表示元素 num 在数组中的下标为 index。

作者：力扣官方题解
链接：https://leetcode.cn/problems/sliding-window-maximum/solutions/543426/hua-dong-chuang-kou-zui-da-zhi-by-leetco-ki6m/

```python 
class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        # 注意 Python 默认的优先队列是小根堆
        q = [(-nums[i], i) for i in range(k)]
        heapq.heapify(q)

        ans = [-q[0][0]]
        for i in range(k, n):
            heapq.heappush(q, (-nums[i], i))
            while q[0][1] <= i - k:
                heapq.heappop(q)
            ans.append(-q[0][0])
        
        return ans
```

### 一、 这段代码是怎么避开“删不掉内部元素”的？

普通堆做不到“直接删掉离开了窗口的元素”，力扣官方题解在这里用了一个非常巧妙的策略——**死不立刻删，等它掉到堆顶了再删**。

#### 核心代码解析：

```python
heapq.heappush(q, (-nums[i], i))  # 1. 只要有新元素，只管压入堆中

# 2. 检查【堆顶】元素是不是已经不在当前窗口里了（下标 <= i - k）
while q[0][1] <= i - k:
  heapq.heappop(q)  # 如果堆顶元素过期了，才把它弹掉

ans.append(-q[0][0])  # 3. 此时的堆顶一定是当前窗口内合法的最大值
```

#### 关键区别：

- **离开窗口的元素如果不影响最大值**：比如窗口是 `[9, 2, 5]`，现在 `2` 离开窗口。`2` 并不是堆顶，代码**完全不管它，任由它留在堆里**。
- **只有当过期元素本身是堆顶时**：`while` 循环才会触发，把它从堆顶弹出。

### 二、 那为什么这种“堆解法”不是最优解？

虽然这种写法的代码很短，并且能通过 LeetCode，但它有两个明显的缺陷：

#### 1. 堆的大小会膨胀，占用更多内存

由于那些已经不在窗口里的“过期元素”没有被立刻删掉，**堆的大小会远远超过 $k$**。

- 在最坏情况下（比如数组是一个递增序列 `[1, 2, 3, 4, 5, 6, ...]`），那些过期的较小元素全都会留在堆里，堆的大小最终会膨胀到 **O(n)**，而不是滑动窗口应有的 O(k) 空间。

#### 2. 时间复杂度退化为 O(n log n)

- 因为堆里最多可能装入 n 个元素，每次 `heappush` 和 `heappop` 的时间复杂度是 **O(log n)**（而不是 O(log k)）。
- 遍历 n 个数，总时间复杂度是 O(n log n)**。
