## 560. [和为K的子数组](https://leetcode.cn/problems/subarray-sum-equals-k/?envType=study-plan-v2&envId=top-100-liked)

### 解法一 : 暴力枚举

```python
class Solution:

  def subarraySum(self, nums: list[int], k: int) -> int:
    count = 0
    # 外层循环：固定子数组的右边界（相当于 Java 中的 start）
    for start in range(len(nums)):
      sum_val = 0
      # 内层循环：从右边界向左逆序累加，枚举所有左边界（相当于 Java 中的 end）
      for end in range(start, -1, -1):
        sum_val += nums[end]
        if sum_val == k:
          count += 1
    return count
```

```go
func subarraySum(nums []int, k int) int {
    count := 0 // 计数器：记录找到了多少个符合要求的子数组

    // 外层循环：遍历数组中的每一个数，把当前这个数作为连续子数组的“结尾”（end）
    for start := 0; start < len(nums); start++ {
        sum := 0 // 用于记录从结尾往左加出来的总和

        // 内层循环：从当前的结尾往左倒着加
        // 比如 start 为 2，内层循环就会依次加 nums[2], nums[1], nums[0]
        for end := start; end >= 0; end-- {
            sum += nums[end] // 把前一个数累加进来

            // 如果当前累加的和正好等于目标值 k
            if sum == k {
                count++ // 找到一个符合条件的子数组，计数器加 1
            }
        }
    }

    return count // 返回总共找到的个数
}
```



这段代码采用的是**穷举法（暴力解法）**。它的思路是：**固定一个右端点（结尾），然后向左累加，寻找符合条件的左端点。**





### 注意点

- **第一个 `-1`（即 `stop`）**：序列的**终点（不包含）**。因为 `range` 是**前闭后开**的（包含起点，不包含终点），所以想让循环一直运行到 `0`，终点必须设置为 `-1`。
- **第二个 `-1`（即 `step`）**：**步长**。负数 `-1` 表示**倒序（递减）**，即每次循环变量递减 1。

它的意思就是：**从 `start` 开始，倒着数到 `0`**。

> **这个算法的核心思路是：** 外层循环用来**确定子数组的右边界**（从左到右依次选定末尾卡片）； 内层循环用来**向左伸展左边界**（不断把左边的卡片拉进来），一边拉一边算总和。

### 代码逻辑解释

这段代码采用的是**暴力枚举法（固定右边界，向左累加）**，通过双重循环枚举出**所有可能出现的连续子数组**并计算其元素和：

1. **外层循环 `start`**：作为子数组的**右边界**（从 `0` 遍历到 `n-1`）。
2. **内层循环 `end`**：作为子数组的**左边界**（从右边界 `start` 开始，反向往左一直遍历到 `0`）。
3. **累加过程 `sum_val`**：在内层循环往左走的过程中，将经过的元素挨个加起来。每次加进一个新元素，就相当于构成了一个新的连续子数组 `nums[end...start]`。
4. **校验判断**：如果当前累加的和 `sum_val == k`，说明找到了一个符合条件的子数组，计数器 `count` 加 1。

> 时间复杂度为O(N ^ 2)

但这个现在在力扣上会超时



### 解法二：前缀和 + 哈希表（复杂度最优）

如果用暴力双重循环遍历所有连续子数组，时间复杂度是 O(n^2)，在数据量较时会超时。最优解法是将题目转换为类似“两数之和”的思想，利用**前缀和（Prefix Sum）+ 哈希表**将时间复杂度降至 O(n)。

> 理解此题请先理解前缀和的题

假设数组为 `nums`，我们要找的是一段连续子数组 `nums[j...i]`，使得它的和等于 k。

我们可以把**子数组的和**转化为**两个前缀和的差**：

- 定义 `prefixSum[i]` 为从第 `0` 个元素加到第 `i` 个元素的总和。

- 那么从 `j` 到 `i` 的连续子数组之和为：

  $$
  \text{Sum}(j, i) = \text{prefixSum}[i] - \text{prefixSum}[j - 1] = k
  $$

通过移项变形得到：


$$
\text{prefixSum}[j - 1] = \text{prefixSum}[i] - k
$$


**结论：** 当我们遍历到当前位置 `i`（当前前缀和为 `current_sum`）时，**只要看之前出现过多少个值为 `current_sum - k` 的前缀和**，就能知道以当前元素结尾、且和为 k 的连续子数组有多少个。

### python 

```python 
class Solution:

  def subarraySum(self, nums: list[int], k: int) -> int:
    count = 0  # 记录满足条件的子数组数量
    current_sum = 0  # 记录当前的前缀和（累加和）

    # prefix_map 用于记录 { 前缀和 : 出现次数 }
    # 预先存入 {0: 1}：代表前缀和为 0 的情况出现了 1 次
    # 用于处理从数组第一个元素开始（nums[0...i]）且和恰好等于 k 的子数组
    prefix_map = {0: 1}

    for num in nums:
      current_sum += num  # 1. 累加当前数字，计算当前位置的前缀和

      # 2. 查找之前是否出现过前缀和为 (current_sum - k) 的位置
      # 如果有，说明这两个位置之间的连续子数组和恰好为 k
      target = current_sum - k
      if target in prefix_map:
        count += prefix_map[target]

      # 3. 将当前的前缀和更新到哈希表中，供后面的元素查询
      prefix_map[current_sum] = prefix_map.get(current_sum, 0) + 1

    return count
```

> **时间复杂度**：O(n) — 只需遍历一次数组，哈希表查找和更新均在 O(1) 时间内完成。



### Go

```go
func subarraySum(nums []int, k int) int {
    // count：符合要求的子数组总数
    // pre：记录当前位置的前缀和（即从开头加到当前的累加和）
    count, pre := 0, 0
    
    // m：哈希表（Map），用于保存历史出现过的【前缀和】以及它【出现的次数】
    // Key = 前缀和的值, Value = 该前缀和出现的次数
    m := map[int]int{}
    
    // 【最关键的一步】初始化 m[0] = 1
    // 意思：前缀和为 0 的情况默认出现过 1 次
    // 作用：如果当前正好有一个从开头 (index 0) 累加到现在的连续子数组本身就等于 k，
    // 那么 pre - k 就等于 0。如果不加 m[0]=1，就会漏掉这种从头开始的合法子数组！
    m[0] = 1

    for i := 0; i < len(nums); i++ {
        pre += nums[i] // 1. 更新当前的前缀和
        
        // 2. 检查历史上有没有出现过值为 (pre - k) 的前缀和
        if _, ok := m[pre - k]; ok {
            count += m[pre - k] // 存在几个，就说明有几个子数组的和恰好等于 k
        }
        
        // 3. 把当前的前缀和记录/更新到哈希表中，供后面的元素查询
        m[pre] += 1
    }
    
    return count
}
```

1. 为什么后面还要加一个 `; ok`？

因为分号前的 `_, ok := m[pre - k]` 只是**创建并赋值了变量**，它本身**不是一个条件判断句**！

- **分号左边 `_, ok := m[pre - k]`（初始化语句）：** 去哈希表 `m` 里查找 `pre - k`。查到的结果赋值给 `_`（忽略），“是否存在”的布尔值结果（`true` 或 `false`）赋值给变量 `ok`。
- **分号右边 `ok`（条件判断）：** 这才是 `if` 真正用来做逻辑判断的表达式！它等价于 `ok == true`



### 注意点

#### 不能使用滑动窗口

谨记： 数组不是单调的话，不要用滑动窗口，考虑用前缀和

在标准滑动窗口中，我们依靠窗口的和（`window_sum`）来决定如何移动指针：

- **纯非负数数组（满足单调性）：**
  - 右指针右移（扩大窗口） ==>  窗口和**一定变大或不变**。
  - 左指针右移（缩小窗口）  ==>  窗口和**一定变小或不变**。
  - 这种确定的变化趋势让我们能够清楚地知道：当和小于 k 时必须右移右指针，当和大于 k 时必须右移左指针。
- **包含负数的数组（单调性失效）：**
  - 右指针右移加入一个负数  ==> 窗口和反而**变小**。
  - 左指针右移移除一个负数  ==>  窗口和反而**变大**。

假设数组为 `nums = [1, 4, -5, 2]`, 目标和 `k = 2`：

1. 当窗口扩展到前三项 `[1, 4, -5]` 时，窗口和为 $1 + 4 + (-5) = 0$。
2. 此时窗口和低于目标值 k = 2。
3. **按照滑动窗口的逻辑**：因为和偏小，只能通过**右移右指针**来试图增大窗口和。
4. 但如果**右移左指针**抛弃 `1` 和 `4`，得到子数组 `[-5]`，或者进一步抛弃 `-5` 留下 `[2]`，和的变化方向完全不可预测。
5. 当你无法根据“当前和与 k 的大小比较”来确切决定**到底是该扩大窗口还是缩小窗口**时，滑动窗口算法的贪心策略就彻底失效了。



| **算法类型**          | **核心机制**                                       | **适用于什么场景**                           | **560 题适用性**                   |
| --------------------- | -------------------------------------------------- | -------------------------------------------- | ---------------------------------- |
| **滑动窗口 / 双指针** | 依靠窗口单调递增/递减来收缩扩展指针                | 数组元素**全为非负数**（或满足严格单调性质） | **不适用**（有负数导致单调性失效） |
| **前缀和 + 哈希表**   | 将连续段转换为点对差：{prefix}[i] - prefix}[j] = k | **通用**（无论正数、负数、零均有效）         | **最优解**（时间复杂度 O(n)）      |



#### 为什么要初始化 `prefix_map = {0: 1}`？

这是最容易遗漏的细节。

**原因：** 处理**从数组第一个元素开始**的子数组。

- 假设 `nums = [3, ...]`, `k = 3`。
- 当遍历到第一个元素 `3` 时，`current_sum = 3`。
- 此时要找的目标前缀和是 `current_sum - k = 3 - 3 = 0`。
- 如果哈希表里没有提前加入 `{0: 1}`，这里就会找不到 `0`，从而漏掉 `[3]` 这个本身就等于 $k$ 的子数组。
- `{0: 1}` 相当于在数组的最前面虚拟放置了一个“前缀和为 0”的基准点。



### Go 语言特性

在 Go 语言中，Map 有一个非常特殊的性质：**如果你查询一个根本不存在的 Key，Go 不会报错，而是直接返回这个类型的“零值”（对于 `int` 类型就是 `0`）。**

所以，`m[pre - k]` 会有两种结果：

1. **如果 `pre - k` 在历史上出现过：**
   - 假设出现过 **2 次**，`m[pre - k]` 的值就是 `2`。
   - 执行 `count += 2`，意味着**找到了 2 个符合条件的子数组**，直接把计数器加 2。
2. **如果 `pre - k` 在历史上从来没出现过：**
   - Go 语言直接返回零值 **`0`**。
   - 执行 `count += 0`，计数器不变，没有任何副作用。
