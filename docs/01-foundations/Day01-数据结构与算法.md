### 框架思维

种种数据结构，皆为**数组**（顺序存储）和**链表**（链式存储）的变换。

### 数据结构的存储方式

数据结构的存储方式只有: 数组 和 链表

- 数组 [顺序存储的基本原理](https://labuladong.online/zh/algo/data-structure-basic/array-basic/)
- 链表 [链式存储](https://labuladong.online/zh/algo/data-structure-basic/linkedlist-basic/)

> 别的数据结构都是这两种基础结构的引申

##### 队列 和 栈

- 这两种数据结构既可以使用链表也可以使用数组实现。用数组实现，就要处理扩容缩容的问题；用链表实现，没有这个问题，但需要更多的内存空间存储节点指针

##### 图 结构

- 邻接表就是链表，邻接矩阵就是二维数组
- 邻接表比较节省空间，但是很多操作的效率上肯定比不过邻接矩阵。

##### 哈希表

- 就是通过散列函数把键映射到一个大数组里

  解决散列冲突? 

  - [拉链法](https://labuladong.online/zh/algo/data-structure-basic/hashtable-chaining/) 使用 **链表** 特性, 但需要额外的空间存储指针
  - 线性探查法 使用 **数组** 特性, 不需要指针的存储空间

##### 树 结构

- 用数组实现就是 [堆]
  - 堆 是一个 完全二叉树,
    - E.g. 二叉堆
- 衍生出各种结构, 二叉搜索树, AVL树, 红黑树, 区间树, B树

```
数组 
- 由于是紧凑连续存储，可以随机访问，通过索引快速找到对应元素，而且相对节约存储空间。
- 但正因为连续存储，内存空间必须一次性分配够，所以说数组如果要扩容，需要重新分配一块更大的空间，再把数据全部复制过去，时间复杂度 O(N)

链表
- 因为元素不连续，而是靠指针指向下一个元素的位置，所以不存在数组的扩容问题；如果知道某一元素的前驱和后驱，操作指针即可删除该元素或者插入新元素，时间复杂度 O(1)
- 但是正因为存储空间不连续，你无法根据一个索引算出对应元素的地址，所以**不能随机访问**；
- 而且由于每个元素必须存储指向前后元素位置的指针，会消耗相对更多的储存空间。
```

    }
}

    // 递归访问 head.val
    traverse(head.next);
}
